# Túttt v0.8.23 — Native Roster Ordering & LiveKit Readiness

**Ngày:** 12/11/2026  
**Nguồn:** v0.8.22  
**Phạm vi:** React Native/Expo, mạng LiveKit, API và tính nhất quán Ivory/Espresso. Không thay luật PK hoặc bố cục web.

## Thay đổi thực hiện

1. **Chống dữ liệu danh sách Live sai thứ tự:** `mobile/src/voice/LiveVoice.ts` sử dụng `rosterReadSeq` để chỉ áp dụng phản hồi roster mới nhất trong cùng phiên. Một thao tác quản lý đã được server xác nhận vô hiệu hóa các bản roster được tải từ trước.
2. **Hàng đợi thao tác quản lý theo phiên:** Các yêu cầu đổi ghế, mời, duyệt, cài đặt và điều phối phòng được thực hiện tuần tự. Khi chuyển phòng, hàng đợi mới tách khỏi yêu cầu treo ở phòng cũ; phản hồi của phòng cũ không ghi đè phòng mới.
3. **Heartbeat một lần tại một thời điểm:** Không phát thêm heartbeat thứ hai khi yêu cầu đầu tiên vẫn treo. Khi kết nối lại, chỉ nhận phản hồi của thế hệ kết nối còn hợp lệ.
4. **Chat mobile:** Bỏ lệnh `POST /rooms/:id/join` bị gọi lại mỗi 3,5 giây trong tác vụ tải tin nhắn. Chỉ `openRoom` chịu trách nhiệm gia nhập; danh sách chat không đổi thì giữ nguyên state, tránh re-render không cần thiết.
5. **Cam ngoài PK trên Native:** Khung camera trống ở chế độ Ivory dùng màu sáng `#F1E7E0`, chữ tối; Espresso giữ nền `#362329` và chữ sáng. Vùng video thực vẫn có lớp phủ riêng để dễ đọc chữ.
6. **Chẩn đoán mạng:** `scripts/preflight_livekit.mjs` kiểm tra API `/api/health`, xác nhận đúng là API Túttt và xem biến cấu hình LiveKit ở backend đã có đủ chưa. Không tải secret/tokens, không xin quyền thiết bị, không giả định âm thanh đã được truyền thành công.

## Chạy kiểm tra từ máy phát triển

```bash
# Trong thư mục dự án
npm test
npm run check:web

# Máy tính và điện thoại phải truy cập được cùng API.
# Ví dụ thay IP và port bằng địa chỉ thực của máy chủ bạn dùng:
npm run preflight:live -- --url http://IP_MAY_CHU:8787 --require-livekit
```

Để thử kết nối từ hai điện thoại, cần:

1. Cài thư viện backend (`npm install --prefix server`) và mobile (`npm install --prefix mobile`) bằng máy có quyền truy cập npm.
2. Cấu hình **ba biến trên server**: `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`. Không đưa key/secret vào `EXPO_PUBLIC_*`, Git hoặc mã JS mobile.
3. Dùng API qua HTTPS tin cậy và URL LiveKit WSS; cấu hình `EXPO_PUBLIC_TUTTT_API_URL` trỏ tới server mà điện thoại thật truy cập được. `localhost` trên điện thoại không phải máy tính phát triển.
4. Dùng Expo **development build** thay vì Expo Go, vì LiveKit dùng native WebRTC. Build Android qua Android SDK; iOS cần macOS/Xcode hoặc hạ tầng build hỗ trợ.
5. Thử nghe/nói hai chiều bằng hai tài khoản riêng, chuyển Wi-Fi/4G, tai nghe Bluetooth, rời/vào cùng phòng, rút mic, tắt/mở quyền, chuyển ứng dụng xuống nền. Ghi nhật ký và chỉ nghiệm thu những gì thực sự nghe/nhìn được.
